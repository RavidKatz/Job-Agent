# Job Agent — מפת פרויקט ובקרה (A→Z)

מסמך זה הוא **מפת הבקרה** של הפרויקט — פותחים אותו בכל פעם שתקועים. הוא מראה
תמיד: מה החזון המלא, מה כבר בנוי, איפה אנחנו תקועים, מה המיקוד הנוכחי, מה הצעד
הבא אחרי כל חסם, ומה אסור לגעת בו עדיין.

תרשימי ה-`Mermaid` נמצאים בקובץ הנפרד [`project-roadmap.mmd`](project-roadmap.mmd)
(תוויות אנגלית לתאימות `Draw.io`). למיפוי טכני מלא ראו
[`architecture.md`](architecture.md) ו-[`architecture.mmd`](architecture.mmd).

> מסמך תיעוד בלבד. אינו משנה קוד, scoring, מקורות משרות או לוגיקת `Claude`.

---

## 1. חזון המוצר

`Job Agent` הופך למוצר private-beta אמין שעוזר לכל אדם למצוא משרות פתוחות
ורלוונטיות מתוך קורות-החיים שלו, ומלווה אותו עד ההגשה.

הזרימה הרצויה: העלאת CV → חילוץ טקסט → פרופיל מועמד מובנה → (אופציונלי) תפקיד-יעד
→ סריקת מקורות → הערכת כל משרה מול הפרופיל → אחוז התאמה + ביטחון + חוזקות + פערים
+ המלצה → שמירה לדשבורד הגשות.

**עקרונות-על:** המוצר `candidate-agnostic` (כל CV = אדם חדש), תפקיד-היעד מכוון
חיפוש אך אינו מחליף ניתוח CV, ותוצאות כנות ומוסברות עדיפות על ציונים אופטימיים.

---

## 2. סטטוס מוצר נוכחי

| יכולת | סטטוס | הערה |
|---|---|---|
| העלאת CV + חילוץ טקסט | ✅ בנוי | `PDF`/`DOCX`/`TXT` דרך `extract_resume.py` |
| בניית פרופיל מועמד | ✅ בנוי | מבוסס-חוקים + העשרת `Claude` אופציונלית |
| תפקיד-יעד אופציונלי | ✅ בנוי | מכוון חיפוש, לא מחליף CV |
| סריקת מקורות משרות | ⚠️ עובד אך איטי | שליפה טורית גורמת לתקיעות |
| מנוע התאמה + scoring | ⚠️ עובד אך שביר | regex/מילות-מפתח, ~2,700 שורות |
| תוצאות מוסברות | ✅ בנוי | אחוז, ביטחון, חוזקות, פערים, המלצה |
| אימות + sessions | ✅ בנוי | cookie + `pbkdf2`, מסד `JSON` |
| דשבורד הגשות | ✅ בנוי | tracker; חסר קישור CV↔הגשה |
| Digest יומי | ❌ לא קיים | Phase B |
| צד מגייסות | ❌ לא קיים | Phase C |

**שורה תחתונה:** השלד עובד מקצה-לקצה. שני כאבים מרכזיים — *מהירות הסריקה* ו*איכות
ההתאמה*.

---

## 3. Phase A — Job Seeker Beta

**מטרה:** כל אדם בישראל שמעלה CV מקבל **במהירות** את המשרות הכי מתאימות, לכל מקצוע.

מה נדרש לסגירת השלב:
- מקבול שליפת המקורות + `timeout` פר-מקור (פותר תקיעות).
- שיפור אמינות איכות ההתאמה (ראו "מפת אינטליגנציה" בהמשך).
- נקודת evaluator אחת (`job-fit.mjs`) כחוזה יציב.
- חוויית סריקה ברורה: סטטוס, near-matches כשאין התאמות, אזהרות איכות גלויות.

**הגדרת הצלחה:** משתמש מעלה CV כלשהו, הסריקה מסתיימת מהר, והתוצאות רלוונטיות
ומוסברות — גם למקצועות שונים זה מזה (מבחן candidate-agnostic).

---

## 4. Phase B — Personal Dashboard + Daily Job Digest

**מטרה:** משתמש רשום מקבל ערך מתמשך, לא רק סריקה חד-פעמית.

מה נדרש:
- שמירת קורות-החיים עצמם פר-משתמש (היום נשמר רק metadata של הגשות).
- קישור כל הגשה ל-CV הספציפי ששימש אותה.
- **Daily Job Digest** — סריקה מתוזמנת שמריצה את הפרופיל השמור מול מקורות חדשים
  ושולחת תקציר משרות חדשות רלוונטיות (אימייל/התראה).
- מעבר מ-`app-db.json` למסד נתונים אמיתי לפני קנה-מידה.

---

## 5. Phase C — Recruiter Side

**מטרה:** אותו מנוע, כיוון הפוך — מגייס/ת מעלה תיאור משרה והמערכת מוצאת את ה-CV
הכי מתאימים.

מה נדרש:
- סוג חשבון "מגייס/ת".
- הפיכת תיאור משרה ל-`jobProfile` כנקודת כניסה סימטרית.
- מאגר מועמדים שניתן לחפש בו (vector store) + דירוג בכיוון הפוך.
- מסד נתונים אמיתי כתנאי קדם.

**הקו המחבר:** שלושת השלבים רצים על **אותו מנוע דו-כיווני** —
`candidateProfile` מול `jobProfile`. המבנה כבר קיים בצורתו ב-`job-fit.mjs`.

---

## 6. ארכיטקטורה נוכחית בקצרה

שרת `Node.js` יחיד (`http` מובנה) שמשרת API + סטטי. שכבות: HTTP (`server.mjs`) →
חילוץ CV (`Python`) → פרופיל (`profile.mjs` + `role-recommender.mjs` + העשרת
`Claude`) → מקורות (`connectors/`) → נרמול ואיכות (`job-model.mjs`) → scoring
(`matcher.mjs`, עם `job-fit.mjs` מעליו) → סינון ו-diagnostics (`pipeline.mjs`) →
אחסון (`auth-store.mjs`, `app-db.json`). Frontend ב-`public/` (vanilla, ללא build).

פירוט מלא: [`architecture.md`](architecture.md).

## 9. מיקוד נוכחי

**תיעוד ומיפוי** — בניית מפת הפרויקט (מסמך זה + מסמכי הארכיטקטורה) כך שתהיה לנו
תמונה ברורה לפני ביצוע. אין כרגע שינוי בקוד production.

לאחר אישור התמונה, המיקוד הביצועי הראשון יהיה **חסם #1 — מקבול שליפת המקורות**
(ROI הכי גבוה, סיכון הכי נמוך, לא נוגע ב-scoring).

## 11. אסור לגעת עדיין (Do Not Change Yet)

- **מנוע ה-scoring** (`matcher.mjs` / `scoreJob`) — מקור-אמת יחיד עד שחלופה תוכח.
- **`config/search-profile.json` ו-`config/sources.json`** — ללא שינוי כוונון/מקורות.
- **לוגיקת `Claude`/`OpenAI`** (`claude-profile.mjs`) — ללא שינוי.
- **אימות ודשבורד** (`auth-store.mjs`, tracker) — עובד, נשאר.
- **חוזה ה-API של `/api/match`** — ה-frontend תלוי בצורת התשובה; כל שינוי מנוע
  חייב לשמר אותה.
- **חילוץ ה-CV ב-`Python`** — לא להחליף עכשיו.

## 12. מפת אינטליגנציית התאמה עתידית

שדרוג ההתאמה בשכבות, מהזול והבטוח לחכם יותר — בלי לזרוק את הקיים:

1. **Rules engine (קיים)** — `scoreJob` הנוכחי. נשאר כבסיס ו-fallback. שיפורים
   נקודתיים בלבד, לא שכתוב.
2. **Embeddings POC (Phase 0)** — מודול מבודד, אופליין, מודד דמיון סמנטי מול
   `scoreJob`. אפס שינוי production, אפס עלות. שער כניסה: דו"ח איכות מדיד.
3. **Semantic reranking** — אם ה-POC מצליח: embeddings מדרגים-מחדש את תוצאות
   ה-rules engine, מאחורי feature-flag. שכבה מוסיפה, לא מחליפה.
4. **AI API רק למשרות המובילות (top jobs)** — `Claude` מפעיל הערכה עמוקה ומוסברת
   רק על מספר קטן של מועמדות מובילות, כדי לשמור עלות נמוכה תוך איכות גבוהה במקום
   שהכי חשוב.

**עיקרון:** כל שכבה נכנסת רק אחרי שהקודמת יציבה ונמדדה. אף שכבה לא מוחקת את
שקדמה לה — הן נערמות.

## 13. צ'קליסט מעבר מ-beta למשתמשים אמיתיים ראשונים

**יציבות וביצועים**
- [ ] מקבול שליפת מקורות + `timeout` פר-מקור (סוף ל-endless loading).
- [ ] סריקה מסתיימת באופן צפוי גם כשמקור נופל (degrade gracefully).
- [ ] בדיקת עומס בסיסית (כמה סריקות במקביל).

**איכות התאמה**
- [ ] מבחן candidate-agnostic על 3+ קורות-חיים ממקצועות שונים.
- [ ] אין משרות לא-רלוונטיות שמוצגות כ-near-match.
- [ ] ציונים מוסברים ולא מנופחים.

**חשבונות ונתונים**
- [ ] רישום/התחברות יציבים; sessions לא נשברים.
- [ ] שמירת CV פר-משתמש + קישור להגשה.
- [ ] גיבוי/שחזור של מסד הנתונים (לפני מעבר ל-DB אמיתי).

**אמון ופרטיות**
- [ ] אזהרות איכות מקור גלויות למשתמש.
- [ ] טיפול ב-CV: לא נשמרים קבצים זמניים מיותרים (`uploads/` מתנקה).
- [ ] מדיניות פרטיות בסיסית לנתוני CV.

**פריסה**
- [ ] `Dockerfile` / `render.yaml` עובדים; `Python` זמין בסביבת הריצה.
- [ ] משתני סביבה מוגדרים (`PORT`, מפתחות אופציונליים) — ללא סודות ב-repo.
- [ ] בדיקת smoke מקצה-לקצה בסביבת ה-beta לפני הזמנת משתמשים.

> פריסה רק לאחר אישור מפורש.
